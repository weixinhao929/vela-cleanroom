# 接口文档（Tauri IPC 命令与事件）

Vela 的「API」是前端 WebView 与 Rust 核心之间的 **Tauri IPC 命令**（192 个，全部在 `lib.rs` 的 `invoke_handler` 注册，以各 `#[tauri::command]` 定义为准）与**事件通道**。无 HTTP REST 接口——唯一例外是 §4b 的本地回环推送入口；下文每个命令即一个接口，「接口地址」为命令名。核对基准：2026-09-28 工作树（`npm run lint:api` 机器对账注册表与本文件，勿手改数字漂移）。

## 1. 通用调用约定

```ts
import { invoke } from "@tauri-apps/api/core";
const tasks = await invoke<RustTask[]>("list_tasks");
await invoke("delete_tasks", { ids: ["a", "b"] });
```

- **参数命名**：JS 侧一律 camelCase（`sortOrder`），Tauri 自动映射 Rust snake_case（`sort_order`）。
- **返回**：Promise；成功返回 JSON 反序列化值，结构见 `src/types/bindings/`（46 个绑定文件，由 `models.rs` / `backup.rs` / `system.rs` / `system_integration.rs` / `net_history.rs` / `media.rs` / `taskbar` / `snip.rs` / `sys_actions.rs` / `hashfile.rs` 的类型经 ts-rs 导出，`npm run gen:types` = `cargo test export`；字段 snake_case）。
- **异常**：reject。两种形态——领域错误为序列化的 `{ message: string }`（DbError）；文件类命令为纯 `string`。调用方统一 `catch` 处理。
- **窗口闸门**（命令级纵深防御，`lib.rs`）：`trusted_window`（settings / widget-\* / snip）覆盖绝大多数系统面命令；`settings_only`（仅 settings）覆盖备份恢复整读文件 / 运行日志 / 崩溃统计 / 重启资源管理器 / localStorage 镜像读取；个别无闸门命令（如 `set_heartbeat_enabled`）只触达无敏感面的运行时标志。闸门拒绝一律 reject（`"untrusted window"` 或 `Denied`），不返回空表/静默假成功——调用方须能区分「被拒」与「真空结果」。
- **写顺序保证**：所有数据库写命令在前端经串行队列排队后发起；Rust 侧单笔超时 60s 由前端判死。

## 4a. 通知历史（DOCK / 通知中心）

自发通知的留档面（db v7 `notification_history`，保留 14 天 / 最多 500 行，写入路径顺手清理；不进 AppData 备份，`reset_app_data` 一并清空）。线协议模型 `NotificationRecord{id, source, title, body, kind, read, created_at}`（ts-rs 导出）。与任务命令同口径，不做窗口闸门。

| 命令                     | 参数                         | 返回                         | 说明                                                                                                                         |
| ------------------------ | ---------------------------- | ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `list_notifications`     | `limit?: number`             | `NotificationRecord[]`       | 新→旧；省略 limit = 全量（表本身有上限）                                                                                     |
| `add_notification`       | `source, title, body, kind?` | `NotificationRecord`         | Rust 生成 id / UTC 毫秒时间戳；kind ∈ pomodoro/todo/info（未知回落 info）；source/title 空串拒绝；字段按字符截断 64/256/1024 |
| `restore_notification`   | `record: NotificationRecord` | `void`                       | 撤销删除：整行原样回插（INSERT OR REPLACE，幂等），重算过期锚点                                                              |
| `read_notification`      | `id`                         | `NotificationRecord \| null` | 单条已读                                                                                                                     |
| `read_all_notifications` | —                            | `number`                     | 全部已读，返回受影响行数                                                                                                     |
| `delete_notification`    | `id`                         | `void`                       | 删除单条                                                                                                                     |
| `clear_notifications`    | —                            | `void`                       | 清空                                                                                                                         |

事件面（前端互播，Rust 仅作总线）：`app:notification`（载荷 `NotificationRecord`，留档成功后由派发窗口广播，多屏 dock/通知中心据此实时入列）、`app:notification-read`（某窗口全部已读，其余窗口本地翻转 read 位不回写）。窗口内另有 DOM 事件 `vela:notification-recorded`（同载荷）。

## 4b. 系统通知（OS toast）与本地 HTTP 推送

| 命令                    | 参数                                | 返回   | 说明                                                                                                               |
| ----------------------- | ----------------------------------- | ------ | ------------------------------------------------------------------------------------------------------------------ |
| `send_os_notification`  | `title, body, source?, instanceId?` | `void` | 发送带点击回调的 Windows toast；任何 webview 可调（来源门控在前端完成），点击激活经 `os-notify:activated` 事件回播 |
| `set_sysnotify_enabled` | `enabled: bool`                     | `void` | 系统通知监听（把系统通知捕获入通知中心留档）的运行时开关；前端持久化镜像负责下次启动，本命令只翻标志               |

**本地 HTTP 推送入口**（`push_server.rs`，无命令面，纯监视线程）：只绑 `127.0.0.1` 的回环 HTTP 服务，默认端口 47310，默认关；开关与端口走设置镜像 `notifications.pushEnabled` / `notifications.pushPort`，监视线程每 2s 重读镜像、变化即关旧监听重建。端点只认 POST（非 POST 405、未知路径 404）：

- `POST /api/notify` `{ title, body, source }` → Rust 校验后向 settings + widget-\* 窗口 emit `push:received`，前端走与系统通知同一条留档 / 灵动岛接管链路（手机转发工具 / 脚本 / 计划任务 / 局域网 Webhook 桥的入口）；
- `POST /api/dispatch` `{ action }` → **7 动作白名单**（toggle-pomodoro / toggle-layer / show-settings / new-task / toggle-palette / toggle-dock / open-dock-panel）走 `shortcuts::dispatch`，与 CLI 命令面同一条分派路径（Stream Deck / AHK / 自动化脚本的远程控制面）。

限制：请求头上限 8KB、Body 上限 64KB，超限 413 断开；任何分支都保证回响应再关连接。

## 9a. 文件删除与撤销（file_history）

删除前先把目标完整复制进应用私有目录，再送系统回收站；撤销从私有备份恢复——不依赖回收站（可能被清空/存储感知清理）。撤销栈上限 100（挤出即删物理备份）；孤儿备份（崩溃残留）保留 7 天；恢复冲突自动唯一化新名（`名称 (2).ext`）；超 256MB 目标不备份、直接普通回收站删除并标注 `undoable=false`。均 trusted_window 门控。

## 10a. 剪贴板历史（CLIP / §4.10）

系统剪贴板的本地留档面（db v8 `clipboard_history` + v10 `files` 列，非置顶行保留 30 天 / 最多 500 行，写入路径顺手清理；置顶行不参与两种清理；不进 AppData 备份，`reset_app_data` 一并清表并清空 `%APPDATA%/clip` 图片目录）。线协议模型 `ClipboardEntry{id, kind, preview, text, image_file, image_w, image_h, image_bytes, source_app, pinned, created_at, files}`（ts-rs 导出；`kind` ∈ text/image/files，图片内容不经 IPC、行内只存文件名，文件条目为 CF_HDROP 路径的 JSON 数组字符串）。

**采集侧**（无命令，Rust 常驻）：`AddClipboardFormatListener` 隐藏窗口 → 工作线程读 CF_UNICODETEXT / PNG 注册格式 / CF_DIBV5 / CF_DIB / CF_HDROP（文件列表）。隐私规则：剪贴板含 `ExcludeClipboardContentFromMonitorProcessing` 格式或 `CanIncludeInClipboardHistory=0` → 不入库；与最新一条内容相同 → 不新增、只刷新时间戳（置顶到最前）；开关（总开关 / 记录图片 / 记录文件 / 记录来源进程 / 纯链接快开弹条，默认 开/开/开/关/开）从设置镜像 `app:settings:v1` 的 `general.clipboard.{enabled,captureImages,captureFiles,recordSource,linkPopup}` 每次捕获实时读取，前端只需正常写 settings-store。

剪贴板内容高度敏感（口令、截图），除打开目录外全部命令 **trusted_window 门控**（settings / widget-\* / snip）。

> **2026-09-19 闸门收口**（详见 `docs/issues-2026-09-19-audit-hardening.md`）：
> `import_data` 升为 **settings_only**（防低信任窗篡改 `app:settings:v1` 劫持更新链）；
> `mirror_local_storage` 分级（受信窗全量 / quick-note 仅便签键 / 其余拒绝）；
> 隐私枚举类（`get_tcp_connections` / `get_network_details` / `get_disk_info` /
> `get_bluetooth_devices` / `get_foreground_app` / `list_media_sessions`）与
> 对话框/文件类（`pick_folder` / `pick_file` / `gallery_delete_file` /
> `save|read|delete_sketch_image`）补 **trusted_window**；
> `fetch_emails` 的 server 字段复用 SSRF 内网守卫。

| `get_taskbar_status`                                                          | —                                                                 | 运行状态快照（注入状态机 phase + 失败/降级原因 + 任务栏类型 + 协议版本；与 `taskbar:status` 事件同型）                                                                                                                                                                                            |
| `get_taskbar_capabilities`                                                    | —                                                                 | 能力回读（`taskbar:capabilities` 事件仅启动/探测时发一次，晚开的设置窗挂载时补读；已探测返回缓存，否则现场探测）                                                                                                                                                                                  |
| `reset_taskbar_state`                                                         | —                                                                 | 重置动态状态：绕过幂等缓存立即重求值全部显示器状态并重应用（托盘「重置任务栏状态」/ 快捷键 `taskbar:reset-state` 同入口）                                                                                                                                                                         |
| `preview_taskbar_state`                                                       | `state?: TaskbarStateKey`，`overrides?: TaskbarPartialAppearance` | 实时预览：临时强制该状态外观到全部任务栏并挂起状态机输出 60s（拖动高频调用合并为 ≤80ms 步进）；`state=null` / 超时 / 真实 apply·reset 即取消；不改配置、不落盘                                                                                                                                    |
| `restart_explorer`                                                            | —                                                                 | 重启资源管理器（DLL 升级残留 `stale_dll_resident` 的闭环动作：taskkill → 等 Win11 自动重生 → 无则 ShellExecute 拉起并轮询确认）。**settings_only**（2026-09-19 从 trusted 收紧：杀 shell 是全桌面级影响，入口本就只在设置页）；由状态条一键按钮或「升级后自动重启」开关触发，应用不擅自结束 shell |

> 任务栏六命令均 `trusted_window` 门控（settings / widget-\*）；任务栏配置完全纳入设置体系（`general.taskbar` 切片，localStorage 权威 + SQLite 镜像 + `sync:settings` 跨窗口同步），无独立配置文件。

## 11a. 单实例 CLI 命令面（cli.rs）

`tauri-plugin-single-instance` 保证单实例：第二实例把 argv 经 WM_COPYDATA 转发给首实例后直接退出（广播 `app:second-instance`，载荷即第二实例 argv）。首实例解析 argv，提供 7 个轻量命令供 自动化工具 / 快捷方式 / 脚本 / E2E 驱动（按出现顺序执行，未知参数忽略）：

```
vela.exe --toggle-layer       显示/隐藏小组件层（同 Ctrl+Alt+D）
vela.exe --show-settings      呼出设置窗口
vela.exe --toggle-pomodoro    开始/暂停专注（同 Ctrl+Alt+Space）
vela.exe --new-task "买咖啡"  直接创建任务；无文本参数则打开新建输入
vela.exe --toggle-palette     全局呼出/收起命令面板（同 Ctrl+Alt+K，层隐藏时先显示）
vela.exe --toggle-dock        显示/隐藏灵动岛（同 Ctrl+Alt+I，仅主屏窗口响应）
vela.exe --open-dock-panel    打开灵动岛全岛面板（同 Ctrl+Alt+O，层隐藏时先显示）
```
