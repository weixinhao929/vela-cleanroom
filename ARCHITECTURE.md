## 1. 项目概述

Focus Desk（界面品牌 **Vela**，crate 名 `focus-desk`，identifier `com.cleanroom.focusdesk`）是一个 Windows 桌面效率应用，采用 clean-room 方式实现，核心能力：

- **桌面小组件层**：每台显示器一个全屏透明置底窗口，承载 34 种注册小组件（时钟、待办、番茄钟、系统监控、音乐、课表、天气、通知中心、剪贴板历史、秒表、贴图等；`misc` 仅灵动岛、`pin` 仅截图钉图内部创建，画布画廊可添加 32 种）。
- **效率三大件**：番茄钟（状态机 + 会话/打断记录）、今日待办、DDL 截止提醒，均支持系统通知与托盘交互。
- **设置主面板**：独立的设置窗口，管理外观、动画、连接、数据备份等全部偏好。
- **系统能力集成**：全局快捷键（可配置 12 动作）、单实例 argv 命令面、系统托盘（一级菜单 13 项）、剪贴板（含历史）、屏幕取色、蓝牙、SMTC 媒体控制（事件化 + 封面取色）、WASAPI 音频频谱、GPU/硬件监控、壁纸跟随主题、亮度控制、在场感知（输入空闲 + 全屏）、截图（冻结帧框选 + 标注 + 钉图）、任务栏自定义（对标 同类任务栏增强工具 形态，XAML 注入）、自研更新链。

代码规模约 14 万行（TS/TSX 10.3 万 + Rust 4.0 万，2026-09-28 实测，含测试），其中前端 `src/` 与 Rust 后端 `src-tauri/src/` 通过 192 个 Tauri IPC command 通信。

## 2. 技术栈总览与选型理由

| 后端      | Rust（edition 2021）                                 | —        | 内存安全 + 无 GC 的长驻后台线程（心跳、系统采样、热插拔监听）；`spawn_blocking` 承载 SQLite 等 IO                                                                                             |

### 3.2 多窗口模型

应用的核心窗口有三类，**全部加载同一个 `index.html`，靠 URL hash 区分身份**（无 react-router）：

| 窗口 label      | 创建方式                                                                                                                                                                              | hash             | 角色                         |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------- | ---------------------------- |
| `settings`      | `tauri.conf.json` 静态声明（1040×720，无边框透明，启动即建）                                                                                                                          | `#/settings`     | 应用主面板                   |
| `widget-<slot>` | `monitor::create_widget_window` 运行时按显示器创建，slot 由「物理显示器名 → 稳定槽位」映射持久化（屏幕清空后由 `reconcile_widget_windows` 对账销窗，见 `widget/window-reconcile.ts`） | `#screen=<slot>` | 每屏一个的全屏透明置底桌面层 |
| `quick-note`    | `windows::show_or_create_quick_note` 按需创建（380×230，置顶，不进任务栏）                                                                                                            | `#quick-note`    | Ctrl+Alt+Q 全局速记          |

除核心三类外还有一批**按需创建的辅助窗口**：`taskbar-net`（任务栏网速条，唯一走独立 `taskbar-net.html` Vite 多页入口的零交互常驻小窗，`taskbar_net.rs` 1s 贴靠线程）、`snip`（`#snip` 截图覆盖窗，冻结帧上框选/标注）、`fullscreen`（`#fullscreen&kind=` 全屏展示窗，命令面板创建）、`super-panel`（`#super-panel` 长按右键取词面板）、`web-preview`（网页浮层，加载远程 URL，capabilities 单独收敛在 `web-preview.json` 最小权限：仅 close + start-dragging，不授予任何自定义命令 IPC）。

关键运行时机制：

- **心跳线程**：Rust 原生线程每秒 `emit("app:heartbeat", now_ms)`。隐藏的 WebView 中 Chromium 会节流 JS 定时器，番茄钟 tick 因此不由 `setInterval` 驱动，而由心跳事件 + 墙钟锚点幂等推进（JS interval 仅作兜底）。
- **单点驱动 + 故障转移**：番茄钟等「单点驱动」逻辑只在主小组件窗口（`widget-0`）运行，primary 失联 5 秒后其余窗口按 localStorage claim 竞选接管，避免多窗口重复计时/重复通知。
- **跨窗口同步**：`lib/cross-window.ts` 通过 Tauri 事件在 `sync:settings` / `sync:widgets` / `sync:view-switch` / `sync:dock` / `sync:app` / `sync:pomodoro` / `sync:habits` 七条通道双向广播（`sync:notes` / `sync:gallery` / `sync:widget-config` / `sync:persist-*` 由各自模块自发）；远端应用时置 `applyingRemote` 标志抑制回声。`sync:settings` 与 `sync:app` 走**三方合并**（叶子级 / 行级，`mergeLeaves` / `mergeRows`）：以上次与对端交换（发射 / 采纳）时的快照为共同祖先，本地编辑只盖时间戳、**不动基线**；远端相对基线没变则保留本地，变了则按 `(ts, json)` 字典序与本地当前值仲裁——两端输入相同必选同一赢家，不会各选各的而永久分叉；`sync:app` 的删除凭显式 `removedTasks` / `removedDeadlines` 凭证（整表缺行不再推断为删除）+ 30s TTL 墓碑防陈旧包复活；保留了对端没有的本地值时回播一次收敛（回播带**指数退避** 0/50/…ms 至 2s 封顶、只对齐基线**不重盖**保留值的编辑时间戳——两窗口时间戳纠缠时立即回播会把收敛变成无界乒乓）。叶子/行比较用 `jsonOf` **规范化序列化**（对象键按字典序、数组保序）：同一份数据在不同窗口持有不同键序（本地 sanitize 字面量序 vs 载荷线序 vs 持久化序）时不再被误判为变更——这是 2026-09-19「设置里快速切换后无限来回切换」同步风暴的根因（见 `docs/issues-2026-09-19-settings-toggle-storm.md`）。`lib/sync-gate.ts`（`withRemoteApply` 门闩）让 settings/app 两 store 的晚到水合写入对同步订阅静默——水合是读库补齐而非用户编辑，不得广播。`sync:widgets` / `sync:dock` / `sync:habits` 按发送方单调 `rev` 拒旧拒重，`sync:pomodoro` 按 `wallMs`。**已知一致性边界（C-3 标注）**：`sync:widgets` / `sync:dock` 是**整包 last-writer-wins**，与 settings/app 通道的三方合并不对称——设置窗与画布窗并发编辑布局时，rev 守卫只能拒旧包、不能合并，后写方的整包会覆盖先写方未广播的改动（一方改动静默丢失）。这是 F-2 编辑会话挂起 + rev 单调性下的刻意取舍，不是遗漏；若需收敛，instances 行结构满足 `{id}` 约束，可按 id 复用 `mergeRows` 行级合并并引入删除凭证/墓碑。`sync:dock` 载荷带 screenId，接收方只采纳同屏配置（设置窗「灵动岛」页的改动即时到桌面层，桌面层不再用陈旧内存态覆盖）。
- **桌面层首帧透明**：`main.tsx` 在 React 挂载前同步给非设置窗口加 `tm-widget-layer` 类，防止水合期间闪出实体背景遮挡桌面。

**单实例 + argv 命令面（`cli.rs`）**

`tauri-plugin-single-instance`（`lib.rs` Builder 首个插件）保证只有一个 Vela 进程常驻：第二实例在插件 setup 阶段（早于建窗/托盘/数据库）把自己的 argv 经 WM_COPYDATA 转发给首实例后直接退出，不会出现双托盘、双心跳、双桌面层。首实例在回调里调 `cli::handle_second_instance(app, argv, cwd)`，`parse_cli` 纯函数按出现顺序解析已识别开关（未知参数忽略），供 自动化工具 / 快捷方式 / 脚本 / E2E 驱动应用：

| 参数                | 行为                                                                                                                                                                                                                                       | 等价入口                                        |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------- |
| `--toggle-layer`    | 显示/隐藏小组件层（`windows::toggle_widget_layer`）                                                                                                                                                                                        | 快捷键 `toggle-layer`（默认 Ctrl+Alt+D）        |
| `--show-settings`   | 呼出设置窗口                                                                                                                                                                                                                               | 快捷键 `show-settings`（默认 Ctrl+Alt+S）       |
| `--toggle-pomodoro` | emit `shortcut:toggle-pomodoro`（primary 窗口统一处理）                                                                                                                                                                                    | 快捷键 `toggle-pomodoro`（默认 Ctrl+Alt+Space） |
| `--new-task "标题"` | emit `tray:new-task`，载荷为标题；无文本参数则载荷空串 = 前端打开新建输入框                                                                                                                                                                | 托盘「新建任务」/ 快捷键 `new-task`             |
| `--toggle-palette`  | `shortcuts::dispatch(app, "toggle-palette")`：层隐藏时先显示 → `widget-0` 临时置顶聚焦 → emit `shortcut:toggle-palette`；面板关闭时前端回发 `command-palette:closed` 撤销编排                                                              | 快捷键 `toggle-palette`（默认 Ctrl+Alt+K）      |
| `--toggle-dock`     | `shortcuts::dispatch(app, "toggle-dock")`：只 emit `shortcut:toggle-dock`——dock 配置按屏独立持久化、不跨窗口同步，由前端 primary 窗口翻转本屏 `dock.enabled`                                                                               | 快捷键 `toggle-dock`（默认 Ctrl+Alt+I）         |
| `--open-dock-panel` | `shortcuts::dispatch(app, "open-dock-panel")`：先 `windows::show_widget_layer`（层隐藏时面板无处可显）→ emit `shortcut:open-dock-panel`，由 primary 窗口展开 `dock:panel`；不做置顶 / 聚焦编排（面板不需要键盘焦点）；岛未启用时前端不动作 | 快捷键 `open-dock-panel`（默认 Ctrl+Alt+O）     |

无论是否识别出指令，首实例都会 emit 一次 `app:second-instance`（载荷 = 完整 argv）作可观测性 / E2E 钩子；全部未识别时写一条 info 日志。`parse_cli` 共识别 7 个开关，其中 `toggle-layer` / `show-settings` 直接操作窗口，其余均与全局快捷键共用 `shortcuts::dispatch` 分派，不另写一份行为。

### 3.3 一条典型数据流（以「添加待办」为例）

```
TodayTasksPanel / QuickNote (features/widget)
  → useAppStore.addTask()                     store 写动作：persist-first 协议
    → sqliteRepo.addTask()                    lib/persistence/sqlite.ts 门面
      → enqueueWrite(invoke("add_task"))      写操作串行进单一 promise 链（60s 超时）
        → commands::add_task                  Rust 门面：参数校验 + spawn_blocking
          → TaskRepo::add()                   行级 SQL，写连接 db（读走 read_db）
            → SQLite（WAL）
      ← 返回 Task（ts-rs 类型 = 前端 bindings 类型）
    ← 落盘成功才更新内存状态 → React 重渲染
  → （其余窗口经 sync:app 事件收到快照）
```

浏览器开发模式下同一条链路在 `sqliteRepo` 处替换为 `localStorageAdapter.save()`——这是端口/适配器架构的直接收益。

**分层依赖规则**（由内向外，允许箭头向内指向；A-1 修订：承认 lib 的双层定位，硬边界交给 `scripts/check-layering.mjs` 门禁钉住）：

```
components/features/widget  →  store  →  ports  ←  lib/persistence（实现）
        │                      │        ↑
        └────→ domain ←─────────┘        └── lib/*（双层：基础设施工具 + 应用中介者）
```

- `domain/` 不依赖任何其他层（纯函数 + Zod，仅可 import 自身与 zod——R1 门禁），可被 store、features、lib 复用；
- `ports/` 只有接口；`lib/persistence` 实现端口，`store` 只依赖端口与门面；持久化适配器不得感知应用状态层（R2 门禁：不 import store/features/widget/app；唯一在案例外：local-storage 的落盘失败提示复用 ToastHost 队列，见门禁 ALLOW 注）；
- `lib/*` 的定位是**双层**（A-1 修订，取代旧「不得反向 import store」的理想态）：一半是基础设施工具（tauri/anim/durations…），一半是**应用中介者**（cross-window/theme-engine/notifications/commands 等，合法 import store——它们实质是跨窗口编排层）。lib 不得反向 import `features/`（UI 消费方，R3 门禁；设置索引搜索经 buildCommands 的 `settingsSearch` 注入，即为此边界的拆除范式）；
- `features/`、`widget/` 是 UI 消费方，只通过 store 动作与 lib 封装触达系统能力，不直接拼 IPC 调用字符串（少数小组件直接 invoke，但均经由文件内封装——A-7 在案例外，新能力优先挂 `lib/<域>.ts`）。

## 5. 核心模块职责与划分

### 5.1 前端状态层（store/）

**`app-store.ts`（`useAppStore`）——核心业务数据的唯一内存事实来源**

- 管理三大领域：待办、截止提醒、番茄钟（含会话与打断记录），以及番茄钟配置；
- **持久化不使用 zustand persist 中间件**，而是自实现 **write-through persist-first 协议**：每个写动作先经 `sqliteRepo`（行级 IPC 命令）落盘成功，再更新内存；失败则内存不变——杜绝「UI 显示成功、重启后回档」；
- 会话/打断记录内存截断（500/300 条），全量数据留在 SQLite；
- `hydrateApp()` 启动水合顺序：解析适配器 →（Tauri 下）一次性 localStorage→SQLite 迁移 → load → 拉会话/打断 → 每日自动备份 → `mergeById` 合并（水合窗口内用户操作获胜、tombstone 剔除已删项）。

**`settings-store.ts`（`useSettingsStore`）——全部用户偏好**

- 切片：外观（2 套内置主题预设「默认/终端」+「自定义」派生档（底色 + 文字色派生，不计入预设数），各带深浅两套 token/themeMode/主色/缩放/字体/透明度/圆角/壁纸文件夹与最近使用…）、general（语言/自启/游戏暂停/减动效/媒体监控行为/双击修饰键呼出 `doubleTapSummon`/超级面板 `superPanel` 等——Rust 侧 `double_tap.rs`/`super_panel.rs` 经设置镜像 2s 轮询读取）、extra（动画开关与速度/视图切换/天气城市/更新源/网速显示与阈值告警等）、notifications（含来源门控 + 本地推送 `pushEnabled`/`pushPort`，`push_server.rs` 同机制读取）；旧版 7 预设快照在 sanitize 时按 `PRESET_MIGRATION` 无损映射；
- 变更流：sanitize → `applySettings`（写 CSS 变量与 `data-*`，主题唯一事实来源）→ `scheduleSave`（350ms 尾随防抖）双后端写：localStorage `focus-desk.settings.v1` + SQLite 镜像键 `app:settings:v1`；`pagehide` 时强制 flush。

**`widget/widget-store.ts`——小组件布局（详见 §5.3）**

三个 store 的持久化策略有意不同：核心业务数据 **SQLite 权威**；设置与小组件布局 **localStorage 权威 + SQLite 镜像**（高频拖拽写不需要每步过 IPC，镜像用于跨窗口兜底与备份）。

### 5.2 持久化子系统（ports/ + lib/persistence/）

| 文件                               | 职责                                                                                                                                                                                                                     |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `ports/persistence.ts`             | `PersistenceAdapter` 接口：`kind / load / save / clear`（曾并存的 `ports/repositories.ts` Task/Deadline/AppState 仓储接口从未被实现或引用，2026-09-14 批次 E 删除）                                                      |
| `lib/persistence/index.ts`         | `resolvePersistenceAdapter()` 策略入口：`isTauri() ? sqliteAdapter : localStorageAdapter`                                                                                                                                |
| `lib/persistence/local-storage.ts` | 浏览器降级实现，键 `focus-desk.state.v1`；Zod 校验，损坏数据改名 `.corrupt-<ts>` 隔离 + toast；配额溢出首次告警                                                                                                          |
| `lib/persistence/sqlite.ts`        | `sqliteAdapter`（load=行级读取，save 显式 no-op——写必须走行级命令）+ `sqliteRepo`（store 动作层门面，聚合全部行级命令）；`enqueueWrite` 把所有写串行进单一 promise 链（防整表替换与行级写交错），单笔 60s 超时；读不排队 |
| `lib/persistence/migration.ts`     | 一次性 `migrateLocalStorageToSqlite()`：浏览器时代数据事务性迁入，行数比对决定重迁，原文保留作回滚，失败不置位下次重试                                                                                                   |

### 5.3 小组件子系统（widget/）

- **`registry.tsx`——注册表模式**：`WidgetMeta{type, name, desc, category, icon, defaultSize, minSize, component}` 数组 `WIDGET_REGISTRY` 共 **34 项**（2026-09-27 以代码为准：focus 8 / tools 11 / system 12 / online 3；4 个复用 `features/` 的功能面板：Analytics/Deadlines/Pomodoro/TodayTasks，其余来自 `widget/widgets/`，`MusicWidget.tsx` 额外导出 `NowPlayingWidget`）。两个特殊条目：`misc` 标 `dockOnly: true`（只入灵动岛，不进画布画廊）、`pin` 标 `hidden: true`（贴图，仅截图钉图流程内部创建，任何 UI 选择器都不列出）——因此「添加小组件」画廊可添加 **32** 项（`!dockOnly && !hidden`，`registry.tsx:773`），灵动岛类型选择器列出 **33** 项（仅 `!hidden`，`DockTypePicker.tsx:161`）。条目另可挂两个可选懒加载面：`ExpandedComponent?`（C1 沉浸页，配 `lazyExpanded`，现有 7 条：todo/analytics/timetable/weather/music/nowplaying/email）与 `MiniComponent?` + `miniSummary?`（灵动岛迷你形态，配 `lazyMini`，见下方 `dock/` 段）。`lazyWidget()` 把具名导出包装为 `React.lazy + memo`——每个小组件独立 chunk（按需加载）且 memo 防拖拽逐帧重渲染内容树。`WIDGET_LOADERS` + `preloadWidgets()` 提供空闲预热。
- **`widget-store.ts`——布局状态**：多视图（默认 home/work/focus + 自建）、`WidgetInstance{x,y,w,h,z…}` 布局与 z 序（上限 2,000,000，定期 renormalize）、回收站（30 天保留 `purgeExpiredTrash`）、命名布局模板、编辑会话瞬态（选中集/对齐参考线/拖拽预览/进出场动画集）。持久化双后端：localStorage 权威 + SQLite 镜像（`widget:views:<N>`、`widget:layout:<N>:<view>` 等，键按屏幕分区），300ms 防抖 + `pagehide` 强制 flush；localStorage 可用即权威、镜像落后自动回写自愈。
- **`WidgetCanvas.tsx`** 桌面画布：按视图渲染全部卡片、编辑模式（拖拽/缩放/8 向对齐/框选/网格/模板）、空白右键全局菜单、首运行播种默认布局。
- **`WidgetCard.tsx`** 单卡片外壳：绝对定位 + z 序、rAF 拖拽（pointerup 一次 commit）、右键菜单（配置/置顶/沉底/复制/穿透/删除）、内部组件经 registry 懒加载 + `Suspense` + 独立 `WidgetErrorBoundary`（单组件崩溃不影响整层）。
- **`WidgetGallery.tsx`** 两栏「添加小组件」模态。
- **`useClickThrough.ts`** 把可交互元素包围盒经 `set_interactive_regions` 持续上报 Rust，配合原生低层鼠标钩子实现「桌面层默认点击穿透、命中控件才拦截」。
- **`dock/`（灵动岛）**：小组件的第二种容器——贴边常驻玻璃条，横排「迷你形态」磁贴，是 C2 Dock 容器在**灵动岛 2.0** 重做后的形态。
  - **数据模型（`widget-store.ts` `DockConfig`，`version: 2`）**：`enabled` / `edge`（`top|bottom|left|right`，左右为 F-11 竖边预留，渲染暂按 top）/ `offset`（岛中心占边长的 0–1 比例，抗分辨率变化）/ `snap`（`start|center|end|free`）/ `style`（`pill|bangs`；bangs = 贴边刘海，仅顶边生效，几何在 `feature-dock.css` SHELL 区段）/ `tiles: DockTile[]`（顺序即排布） / `mouse{hover,blank,middle,wheel}` / `takeover{pomodoro,media,notification,durationMs}` / `autoHide`（`never|fullscreen|idle`）/ `panel{mode}` / `density`（36|42|48）。`DockTile{id, type, instanceId?, config?}`：`id` 为 uuid，是排序 / 移除 / 展开 id 的键；`type` 是 registry 类型 id；`instanceId` 绑定画布实例并共享其 `widget-config`，`config` 仅在无实例时作磁贴私有配置。默认值单一来源是 `dock/dock-logic.ts` 的 `DOCK_DEFAULTS`（`enabled: false`——升级后不会凭空多出一条岛，首运行播种默认布局时一并开启），`widget-store.ts` 的 `DEFAULT_DOCK` 在其上拼三枚固定 id 默认磁贴（`dock-tile-clock` / `-pomodoro` / `-notifications`，稳定可断言）。
  - **持久化与 v1→v2 迁移**：按屏分区——localStorage `focus-desk.screen.<N>.dock.v1` 权威 + SQLite `widget:dock:<N>` 镜像（键名里的 `.v1` 是历史命名，格式版本由内容里的 `version` 字段区分，故不再多一次数据迁移；键风格对齐 `bar-pos.v1`；不进 `sync:widgets`，而是经独立的 **`sync:dock`** 通道带 screenId 跨窗口同步，接收方只采纳同屏——A 屏开关 / 选边不影响 B 屏）。`parseDockConfig` 以「无 `version >= 2`」识别 v1 载荷（`tiles` 为字符串数组）→ `dock-logic.migrateDockConfig` 纯函数迁移（`enabled`/`edge` 合法值保留、逐枚磁贴换成 `{id: idGen(), type}`、其余字段回默认、未知与重复类型剔除），`loadDock` 对 v1 载荷迁移后立即回写 v2——磁贴 uuid 首启即固定，后续以 `tile.id` 为键的展开 id / 逐磁贴配置不漂移。v2 路径另做字段级校验（tiles 剔非法并按 id 去重、offset 钳 0–1、durationMs 钳 3–15s、density 只收 36/42/48、`autoHideIdleSecs` 钳 60–3600s、`topInset` 钳 0–64px）；默认值经 `cloneDockDefaults()` 深拷贝，`mouse`/`takeover`/`panel` 子对象绝不与模块常量共享引用。新动作：`addDockTile(tile, index?)`（强制入岛去重 `findDockTileConflict`：磁贴身份 = 绑定实例取 instanceId、否则取 type，同身份只保留一枚；四条入岛入口据此渲染禁用态）/ `removeDockTile(id)` / `moveDockTile(id, toIndex)` / `setDockPlacement({edge?,offset?,snap?})` / `setDockTileConfig(id, patch)`，`setDock(patch)` 保留给岛级开关项；拖拽瞬态 `dockDrag{pointer, overIsland, insertIndex}` 只存内存不落盘。**绑定实例失效对账** `reconcileDockTiles()`：绑定实例被永久删除（清空 / 逾期清理回收站、删视图、整表替换）时磁贴降级为无实例磁贴并派发 `vela:dock-tiles-degraded`（DockShell 弹一次性 toast）；移入回收站不触发。触发点：画布 hydrate 完成、上述 store 动作、`switchScreen`、收到 `sync:widgets` 之后。
  - **目录拆分（`dock/`，由原单个 351 行 `DockContainer.tsx` 拆出，`DockContainer` 已删除；共 23 个文件 = 10 组件 + `dock-logic.ts` + 12 测试）**：`DockShell.tsx`（岛本体：按 `edge` 贴边 + 由 `offset`/`snap` 决定沿边位置；编辑模式拖动柄逐帧只写 transform、松手 `snapOffset(中心比例, 屏宽, 32)` 一次 `setDockPlacement` 落盘并 FLIP；指针进入对侧 25% 屏高带（`EDGE_SWITCH_BAND`）预览换边；hover 微涨 `is-peak`；`autoHide` 订阅 `presence:state`；外形 `style="bangs"` 挂 `is-bangs`；接管 hook 装配与磁贴矩形采集 `tileRefs`；鼠标动作路由）/ `DockTiles.tsx`（磁贴层：按 `tiles` 顺序渲染，接管期整层 aria-hidden + 磁贴失焦；岛内拖动排序走 `insertionIndexAt` + FLIP、拖出岛 = 移除并给「撤销」toast；键盘 `←/→` / `Home/End` / `Ctrl+←/→` / `Delete` / `Enter`）/ `DockTile.tsx`（单磁贴：按 registry 分派 `MiniComponent` → 否则通用磁贴 `icon + name`（+ 可选 `miniSummary`）；点击 → 展开 `dock:<tileId>`；展开内容依次为内置三面板 → `meta.ExpandedComponent` → 完整 `meta.component`；右键 / 长按 600ms → `ContextMenu`：配置（就地弹层）/ 从灵动岛移除（可撤销）/ 在画布中定位 / 更多设置）/ `DockDropZone.tsx`（画布卡片拖入：`store.subscribe` 同步订阅 `dockDrag`，会话开始缓存岛矩形（外扩命中边距）与磁贴矩形，命中高亮 + 插入位预览 + 幽灵芯片；松手默认复制为磁贴，按 `Alt` 走移动语义）/ `DockPanel.tsx`（全岛面板 `dock:panel`：按 `tiles` 顺序渲染全部卡片，轮播 / 网格两视图（读 `dock.panel.mode`，右上角有会话内切换），卡片内容按 registry 分派 `ExpandedComponent` → 完整 `component`）/ `DockTakeover.tsx`（`useDockTakeover` 候选接线 + 接管条）/ `DockShortcuts.tsx`（`shortcut:toggle-dock` / `shortcut:open-dock-panel` 响应，仅 primary 窗口）/ `DockConfigPanel.tsx`（编辑模式浮层的快捷项：启用 / 贴边 / 位置吸附 + 自由偏移滑条 / 悬停行为 / 接管三开关 + 磁贴芯片 ↑↓ 排序与「+」）/ `DockTileConfigPopover.tsx`（单磁贴就地配置弹层，从 `DockTile` 右键「配置」拆出）/ `DockTypePicker.tsx`（「+」的类型选择器：按 `CATEGORY_NAMES` 分组列出全部 registry 类型，顶部搜索走 `match-tier` 五级评分，复用 `WidgetConfigPopover` 的定位与 160ms 延后退场）/ `dock-logic.ts`（纯函数与常量：`migrateDockConfig` / `insertionIndexAt` / `snapOffset` / `resolveTakeover` / `DOCK_DEFAULTS` / `DOCK_EXPAND_PREFIX` / `dockTileExpandId`）。设置窗口的全量项在 `features/settings/pages/DockPage.tsx`（「灵动岛」页），与浮层读写同一份配置。样式在 `styles/feature-dock.css`，按 `SHELL / TILES / TILE / DROP / PANEL / TAKEOVER / CONFIG / MINI` 区段划分。
  - **迷你形态（registry + `widgets/mini/`）**：`WidgetMeta` 增可选 `MiniComponent?: MiniComponentType`、`miniSummary?(instanceId?) => string` 与 `miniSummarySubscribe?(instanceId, onChange) => unsubscribe`（G8：摘要数据源订阅，DockTile 据此在数据变化时重算摘要行）；props 为 `MiniComponentProps{instanceId?, active}`；`lazyMini(loader, key)` 与 `lazyExpanded` 同构（`lazy + memo`，独立 chunk，首次入岛才拉取）。**任何 registry 类型都可入岛**，只是有无富形态：已登记富迷你形态 **14 种**（注册 `MiniComponent` 的条目 **15**——`MusicWidget` 与 `NowPlayingWidget` 共用 `MusicMini`），各自一个独立小文件 `widgets/mini/<Type>Mini.tsx`（Clock / Todo / Pomodoro / System / Calendar / Weather / Music / Habit / Countdown / Notifications / Brightness / Clipboard / Stopwatch / Misc；`PomodoroRing` / `usePomodoroView` 由 `PomodoroMini` 导出供展开面板复用），未登记的类型一律走 `DockTile` 的通用磁贴——其中今日概览 / 截止日期 / 便签 / 回收站 / 快捷方式 / 桌面文件六类的 `miniSummary` 为实时数据（app-store / widget-store 快照或 widget-config / localStorage 读取，订阅变更自动刷新；便签无事件源，30s 低频自刷）。
  - **入岛与展开**：入岛三条入口——画布卡片拖入（`DockDropZone`，`WidgetCard` 拖动 rAF 写 `dockDrag`、松手命中岛改走 `addDockTile`）、编辑模式「+」类型选择器（`DockTypePicker`）、「添加小组件」图库的「添加到灵动岛」。展开复用 C1 展开态框架——`expand-store` 单值互斥（磁贴 id 前缀 `dock:` + `tileId`，全岛面板固定 `dock:panel`，常量收敛在 `dock-logic`，与画布实例 id 区隔；与沉浸页互相顶掉）+ `WidgetExpandOverlay` 几何动画（常驻叠放不重建）。
  - **接管链（F-8 可配置）**：`dock-logic.resolveTakeover` 实现互斥优先级链（番茄钟响铃 > 亮度 / 音量 / 媒体切歌（同级最新者胜） > 通知到达，默认 6s 回落）；五个 kind 开关经 `enabledKinds` 传入（缺省 / 缺项 = 开启，被关 kind 的候选直接丢弃），展示时长读本屏 `dock.takeover.durationMs`（默认与 `TAKEOVER_MS` 同源 6s），候选被接受才套用配置时长、被丢弃的候选不动在途到期。接管条点击：目标类型在岛上 → 展开其磁贴，不在 → 仅回落（不自动添加磁贴）。媒体候选来自 `media:snapshot` 事件（Rust 仅变化才 emit）；亮度 / 音量的**应用内调整**候选来自广播的 `focus-desk:osd` DOM 事件（`lib/osd-events.ts`；画布亮度卡滑杆与音乐卡滚轮发，岛内 BrightnessMini 不发——接管会藏起正在拖动的磁贴层），**系统侧音量变化**（硬件音量键等）则由 `audio_events.rs` 发 `osd:volume` Tauri 事件，DockTakeover 同样监听。动效规范见 [docs/ui-guidelines.md](docs/ui-guidelines.md) §4。
- **`notifications/`（方案 D 通知中心）**：`notification-store` 是通知历史的内存镜像（SQLite v7 权威，新→旧，上限 200；实时经 DOM 事件 `vela:notification-recorded` 与 Tauri 事件 `app:notification` 推入并按 id 去重；乐观删除 + undo 槽）；`NotificationCenterList` 为小组件与 dock 面板共用主体（按来源分组折叠 / 70px 阈值滑动删除 + 邻卡 0.3×/0.1× 弹性跟随 / 恢复 / 免打扰 / 一键清除 / 空状态）。`lib/notifications.ts` 的三条自发派发路径门控通过即留档；`lib/system-notify.ts` 系统事件路由把系统侧来源（其它应用 Toast `sysnotify:captured`、复制纯链接 `clipboard:url` 等）也汇入同一历史；`lib/dnd.ts` 免打扰只压制 toast/系统通知/提示音，不压制留档。

### 5.4 Rust 后端模块

**数据链路（核心四件套）**

- `db.rs`：连接与迁移。WAL、`foreign_keys=ON`、busy_timeout 5s；**MIGRATIONS 共 10 版**（v1 初始五表 → v2 打断日志 → v3 截止完成 → v4 任务字段扩展 → v5 会话归因 → v6 时间戳归一 UTC 毫秒 → v7 通知历史表 `notification_history` → v8 剪贴板历史表 `clipboard_history`，两者均以行级 `expires_at` 为过期锚点 → v9 按天流量表 `net_traffic_daily` → v10 `clipboard_history` 增 `files` 附件列）；`open_and_migrate` 失败重试 3 次（退避 250/500/750ms），仍失败则把库文件改名为 `*.corrupt-<ts>` 归档重建（保启动不保数据，由每日备份兜底）；读写两条连接（`db` 写 / `read_db` 读）；`lock_db()` 中毒锁恢复。
- `models.rs`：全部 `#[derive(TS)]` + `#[ts(export, export_to = "../../src/types/bindings/")]`——Task、Deadline、PomodoroSession、DailyFocusStat、FocusAggregate、PomodoroInterruption、SettingKV、AppData、ImportResult、NotificationRecord、ClipboardEntry、WallpaperPalette(Info)。`i64` 一律 `#[ts(type = "number")]`（ts-rs 12 默认导出 bigint），`Option<i64>` 用 `"number | null"`。
- `repositories.rs`：行级 SQL 仓储。`TaskRepo` / `DeadlineRepo` / `SessionRepo`（含 SQLite 按日聚合）/ `InterruptionRepo` / `NotificationRepo`（通知历史：保留 14 天 / 最多 500 行，过期与超量清理在写入路径顺手执行，不进 AppData 备份）/ `ClipboardRepo`（剪贴板历史：与最新一条哈希相同只刷新时间戳「去重置顶」；非置顶行 30 天 / 500 行 LRU，置顶行免清理；删行回报图片文件名由调用方删文件，仓储不碰文件系统）/ `SettingsRepo` / `BackupRepo`（整库导出/导入），另有 localStorage 镜像表读写（`lsmirror:%` 前缀行）。
- `commands.rs`：门面层。参数校验 + `spawn_blocking` + `lock_db`，读命令走 `read_db`、写命令走 `db`；批量操作（`delete_tasks`/`reorder_tasks`）单事务；通知历史 7 命令（`list/add/restore/read/read_all/delete/clear_notifications`，见 docs/API.md §4a）；`reset_app_data` 连带清空剪贴板历史表与 `clip` 图片目录。

### 6.3 模块间依赖图（简化）

```
features/* ─┬─→ store/app-store ─┬─→ ports/* ←─ lib/persistence/sqlite ──→ invoke ──→ commands.rs ──→ repositories.rs ──→ db.rs
widget/*  ─┤                    │                                        (sqliteRepo 门面)

settings   ─┴─→ store/settings-store ─→ localStorage + sqliteRepo.setSetting（双写）
```

**Rust 侧依赖方向**：`lib.rs` →（`commands` / 各能力模块）；`commands.rs` → `repositories.rs` → `db.rs`；能力模块彼此独立，几乎不互相依赖（`monitor.rs` 与 `windows.rs`、`tray.rs` 与 `lib.rs` 除外）。

## 7. 关键设计模式与技术决策

| #   | 模式/决策                            | 落点                                                                                            | 解决的问题                                                                                                     |
| --- | ------------------------------------ | ----------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 1   | **六边形架构（端口/适配器）**        | `ports/persistence.ts` + `lib/persistence/*`                                                    | 同一份业务代码在浏览器（localStorage）与桌面（SQLite）两种运行时下工作；未来换 Tauri Store/云同步不动 store 层 |
| 2   | **Repository 模式**                  | Rust `repositories.rs` 八仓储；前端经 `sqliteRepo` 门面调用                                     | 领域逻辑与 SQL 解耦                                                                                            |
| 3   | **ts-rs 单一事实来源类型生成**       | `models.rs` `#[ts(export)]` → `npm run gen:types`（`cargo test export`）→ `src/types/bindings/` | IPC 线协议只定义一次；snake_case→camelCase 映射由生成物 + `toTask()` 转换器保证，杜绝手写漂移                  |
| 4   | **注册表 + React.lazy + memo**       | `widget/registry.tsx`                                                                           | 新增小组件零侵入（登记两条即可）；每组件独立 chunk 控首屏体积；memo 隔离拖拽重渲染                             |
| 5   | **策略模式**                         | `resolvePersistenceAdapter()`                                                                   | 运行时环境判别集中在一点，消费方无分支                                                                         |
| 6   | **门面模式**                         | `commands.rs`（校验/阻塞/连接选择）、`sqliteRepo`（前端写链）                                   | 统一横切关注点：安全门控、spawn_blocking、写串行化、超时                                                       |
| 7   | **中介者模式**                       | `lib/tray-events.ts`、`lib/cross-window.ts`                                                     | 托盘/跨窗口事件在单一模块翻译成 store 动作，UI 树不感知事件拓扑                                                |
| 8   | **write-through persist-first 协议** | `app-store.ts` 写动作                                                                           | 先落盘后改内存，失败即拒绝——消除「重启回档」类缺陷                                                             |
| 9   | **单点驱动 + 选举故障转移**          | `App.tsx` primary/standby ticker                                                                | 多窗口只有一个计时器在跑，primary 失联 5s 后按 claim 接管                                                      |
| 10  | **原生心跳驱动**                     | `lib.rs` 心跳线程 → `app:heartbeat`                                                             | 规避隐藏 WebView 的 Chromium 定时器节流；墙钟锚点幂等                                                          |
| 11  | **读写分离 + 写串行化**              | `read_db` 第二连接；`enqueueWrite` promise 链                                                   | 读不被写阻塞；行级写与整表替换（备份恢复）不交错                                                               |
| 12  | **纵深防御窗口门控**                 | capability 白名单 + `trusted_window`/`settings_only_window`                                     | 多窗口共用 bundle，敏感命令按窗口身份限权（读日志/读文本仅设置窗）                                             |
| 13  | **自研更新链**                       | `system_integration.rs`：禁自动重定向 + 同域校验 + SHA-256                                      | 不依赖 Tauri updater 插件的签名/服务端假设，安全属性可审计                                                     |
| 14  | **单入口 + hash 路由**               | 一个 `index.html`，`#/settings`、`#screen=N`、`#quick-note`                                     | 多窗口共享一份构建产物；样式与视图按窗口分包，设置窗不背负小组件 CSS，桌面层不加载 settings.css                |
| 15  | **降级而非崩溃**                     | 损坏 SQLite 归档重建、localStorage `.corrupt-` 隔离、水合 4s 安全网、单组件 ErrorBoundary       | 桌面应用的可用性优先：局部故障不拖垮启动与整层桌面                                                             |

## 8. 构建与部署流程

### 8.1 前端构建（Vite）

`npm run build` = `tsc -b && vite build`（先类型检查后打包）：

- **target**：`TAURI_ENV_PLATFORM=windows` → `chrome105`（WebView2），否则 `safari13`；
- **分包**：`manualChunks` 拆 `vendor-icons`（lucide-react，判定必须先于 react，因其包名含 "react"）/ `vendor-react`（react-dom+react+scheduler+zustand+use-sync-external-store 必须同 chunk，避免循环）/ `vendor-tauri` / `vendor`；小组件与设置视图靠动态 `import()` 自动切 chunk；
- **样式分包**：`main.tsx` 按窗口 hash 静态/动态加载样式，设置窗与桌面层互不背负对方 CSS；
- **产物**：`dist/`（`frontendDist`），`define.__BUILD_TIME__` 注入构建时间。

### 8.2 桌面构建与打包（Tauri）

```bash
npm install                 # 前端依赖
npm run tauri dev           # 开发：起 Vite(1420) + Rust 增量编译 + 热窗口
npm run tauri build         # 发布：vite build → cargo build --release → 打安装包
```

前置条件：Rust stable、Windows WebView2、VS C++ Build Tools。打包配置在 `tauri.conf.json` `bundle` 段（`targets: "all"`，图标 png/icns/ico），实际产出 NSIS 与 WiX（MSI）两种安装器到 `src-tauri/target/release/`（`bundle/` 子目录）；已验证产出 `Vela_0.1.0_x64-setup.exe`（约 7.4 MB）与 `Vela_0.1.0_x64_en-US.msi`（约 10.0 MB，2026-09-27 实测，见 `docs/releasing.md` 清单示例）。

### 8.4 发布链路

1. `npm run tauri build` 产出安装器；
2. 更新走**自研链**而非插件：用户配置更新源（`extra.updateEndpoint`）→ `check_updates`（同域校验）→ `download_update`（SHA-256 完整性校验）→ `install_update`；
3. 崩溃与日志：`logging.rs` 按天滚动（`app_data/logs/vela-YYYYMMDD.log`，保留 7 天），设置页诊断区可 `open_log_dir`/`read_recent_log`；
4. 数据兜底：`backup.rs` 每日自动备份（保留 30 份）+ 设置页手动备份/恢复（`BACKUP_SCHEMA_VERSION` 控制格式兼容）；
5. **发布校验链**（详见 [docs/releasing.md](docs/releasing.md)）：`scripts/release/sum.ps1` 对 `bundle/` 下 `nsis/*.exe`、`msi/*.msi` 逐项算 SHA-256，连同大小与版本号（硬校验 `package.json` 与 `tauri.conf.json` 一致）写入 `SHA256SUMS`；加 `-Sidecars` 另生成每个产物旁的 GNU 兼容 `<产物>.sha256`——自研更新链 `download_update` 会请求同目录 `<url>.sha256` 取期望哈希，缺了直接校验失败 → `scripts/release/verify.ps1` 按清单逐项核对存在 / 大小 / 哈希并扫描清单外多余产物（exit 0 通过 / 1 篡改缺失多余 / 2 清单损坏）→ CI `release-verify` job（`.github/workflows/ci.yml`，仅 `workflow_dispatch` 手动触发）在 windows runner 上完整跑 构建 → sum → verify → 篡改自测（翻转副本一个字节，断言 verify 非零退出）。安装包与 `SHA256SUMS` 一起作为 Release 附件发布；未做代码签名（SmartScreen 拦截需在 Release 说明中告知）。

## 10. 扩展指引

**新增一个小组件**：

1. 在 `src/widget/widgets/` 写组件（可调 `lib/*` 封装或 IPC 命令）；
2. 在 `registry.tsx` 的 `WIDGET_REGISTRY` 登记 `WidgetMeta`、`WIDGET_LOADERS` 登记 loader（可选：`config-schemas.ts` 加配置 schema）；
3. 需要新系统能力时在 Rust 侧加模块/命令，并考虑是否需要 `trusted_window` 门控。

**可选：给小组件加迷你形态（入岛用）**：

1. 在 `src/widget/widgets/mini/` 写 `<Type>Mini.tsx`——具名导出，签名 `(props: MiniComponentProps) => JSX`，只读 store / 订阅事件，**不发起自己的轮询**（复用卡片已有的数据源）；
2. 在 `registry.tsx` 用 `lazyMini(() => import("./widgets/mini/<Type>Mini"), "<Type>Mini")` 包一层；
3. 对应 `WidgetMeta` 加 `MiniComponent`（可选 `miniSummary(instanceId?)` 供通用磁贴 / 无障碍标签显示一行摘要）。
   未登记迷你形态的类型也能入岛，由 `dock/DockTile.tsx` 降级为通用磁贴（`icon + name`）。

**新增一个领域实体**：

1. `models.rs` 加 `#[derive(TS)] #[ts(export)]` 模型 → 跑 `npm run gen:types`；
2. `db.rs` 追加一版 `MIGRATIONS`（只增不改历史版本）；
3. `repositories.rs` 加仓储 → `commands.rs` 加门面命令 → `lib.rs` 注册；
4. 前端 `sqliteRepo` 加门面方法 → store 加 persist-first 动作。

**新增一个设置项**：`settings-store.ts` 对应切片 + sanitize + 默认值，跨窗口生效由 `sync:settings` 自动覆盖。
